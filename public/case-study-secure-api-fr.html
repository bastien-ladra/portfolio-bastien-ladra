01 · Modèle système

La sécurité suit l'artefact.

L'API reste volontairement simple afin que le sujet principal reste inspectable : comment protéger le code, les dépendances, le conteneur, l'infrastructure, la publication et le comportement HTTP jusqu'au runtime.

InfrastructureTerraform · Trivy config

Chaque étape correspond à des fichiers de workflow ou d'infrastructure directement inspectables dans le dépôt public.

Dépendances reproductibles

Les dépendances runtime et développement sont installées depuis des lockfiles avec hashes. La CI régénère les locks et bloque toute dérive.

Entrées de build immuables

Images de base épinglées par digest, build multi-stage et runtime distroless non-root. Les actions critiques sont également épinglées sur des commits.

Sorties traçables

Les images publiées reçoivent une provenance signée et une attestation SBOM CycloneDX liée au digest du conteneur.

03 · Preuves de contrôle

Sept workflows, sept responsabilités lisibles.

Les contrôles sont séparés afin qu'un reviewer puisse comprendre ce qui protège chaque étape et identifier précisément l'origine d'un échec.

CI

Tests Python, Gitleaks et contrôle de dérive des lockfiles avec installation par hashes.

CodeQL

Analyse statique séparée des tests fonctionnels pour garder un signal sécurité dédié.

Dépendances

Dependency Review évalue les changements introduits par les pull requests.

Conteneurs

Trivy bloque les vulnérabilités HIGH/CRITICAL corrigibles puis produit un SBOM CycloneDX.

DAST

L'API est lancée en conteneur, health-checkée puis analysée avec une image OWASP ZAP épinglée par digest.

IaC

Terraform fmt/init/validate/test complété par un scan Trivy de configuration bloquant.

Publication

Image GHCR par SHA de commit, provenance signée et attestation SBOM liée au digest.

05 · Limites

Ce que ce projet ne prétend pas.

Une étude de cas sécurité crédible doit montrer ses frontières. Ce dépôt est une implémentation de référence, pas une plateforme de production complète.

Pas d'authentification métier

Cloud Run IAM limite l'invocation anonyme sur la cible Terraform, mais l'API ne modélise pas d'identité ou d'autorisation applicative métier.

Pas de stack de détection runtime

Les probes servent à la disponibilité. Logs d'audit structurés, alerting, runtime detection et télémétrie d'incident restent hors périmètre.

DAST baseline, pas exhaustif

OWASP ZAP baseline apporte une couverture de régression utile mais ne remplace pas un scan actif authentifié, des tests manuels ou un pentest ciblé.

Choix de conception : privilégier quelques contrôles bloquants, compréhensibles et falsifiables plutôt qu'une collection de scanners produisant du bruit.

06 · Pont vers la recherche

De la provenance logicielle à la provenance IA.

Le projet sert de base concrète pour explorer le Secure MLOps : révision du code modèle, lignée et intégrité des datasets, digest et signature des modèles, provenance d'entraînement et validation comportementale.

Question de recherche

Comment étendre les garanties de la supply chain logicielle aux modèles, datasets et pipelines ML tout en restant praticable pour les équipes d'ingénierie ?
